# Linux正则表达式

## 总结

正则表达式用于匹配文本模式。BRE核心是^、$、.、[]、[^]、*和反斜杠；ERE在此基础上增加|、()、?、+和次数限定。正则中的*只重复前一个元素，任意字符串通常写成.*。

## 通配符与正则

Shell文件名通配：

    *.rpt

正则文本模式：

    .*\.rpt$

二者虽然都使用*，含义不同。

## BRE基本正则

| 符号 | 含义 |
|---|---|
| ^ | 行首 |
| $ | 行尾 |
| . | 任意一个非换行字符 |
| [] | 集合中的任意一个字符 |
| [^] | 不属于集合的一个字符 |
| * | 前一元素出现零次或多次 |
| \ | 转义特殊字符 |

示例：

    ^ERROR
    completed$
    ^$
    cl.ck
    cl[oa]ck
    cl[^o]ck
    ^cl.*k$
    \.

## 单词边界

GNU grep常用：

    \<clock\>

用于匹配完整单词clock，而不是clocks的一部分。

## ERE扩展正则

使用：

    grep -E "pattern" file

| 符号 | 含义 |
|---|---|
| \| | 或 |
| () | 分组 |
| ? | 前一元素零次或一次 |
| + | 前一元素一次或多次 |
| {n,m} | 出现n至m次 |
| {n,} | 至少n次 |
| {n} | 恰好n次 |

示例：

    ERROR|WARN
    WARN(ING)?
    ^clo+ck$
    [0-9]{3}

## 引号

正则模式通常使用单引号：

    grep -E 'error|warn' file

可以避免Shell提前解释$、*、反斜杠等字符。

## 易错点

- 正则中的.不是字面句点；字面句点写成\.。
- 正则中的*不能单独理解为任意内容。
- ^在方括号外表示行首，在[^...]中表示集合取反。
- grep默认BRE；使用-E启用ERE。
- a{n}表示恰好n次，不是最多n次。

## 数字后端应用

- 匹配ERROR、WARN或WARNING。
- 匹配报告中的负数、路径或阶段名。
- 为后续regexp、regsub和日志解析建立基础。

## 自检

- 能解释.*与Shell中的*。
- 能写出行首、行尾和空行模式。
- 能用ERE同时匹配多个关键词。
- 能解释WARN(ING)?。
